## 🔴 Критичные исправления (ASAP) ✅ ВЫПОЛНЕНО

### 1. Валидация Telegram WebApp initData ✅
**Проблема:** Используется `initDataUnsafe` без проверки подписи  
**Решение:** Добавлена серверная валидация подписи initData через HMAC-SHA256  
**Реализовано:**
- ✅ `lib/telegram-validation.ts` - утилита для проверки подписи
- ✅ `app/api/auth/telegram/route.ts` - валидация initData перед авторизацией
- ✅ `components/telegram-provider.tsx` - отправка initData строки на сервер
- ✅ `lib/telegram.ts` - функция `getTelegramInitData()` для получения initData строки

**Приоритет:** 🔥 Критично для безопасности

---

### 2. Полная валидация initData на сервере ✅
**Проблема:** Клиентская авторизация через Telegram не проверяет подпись  
**Решение:** Все запросы с `initData` проходят серверную валидацию  
**Реализовано:**
- ✅ `app/api/auth/telegram/route.ts` - полная валидация с проверкой подписи и срока действия
- ✅ `lib/middleware/telegram-auth.ts` - утилиты для проверки initData в API routes
- ✅ Поддержка legacy flow для обратной совместимости

**Приоритет:** 🔥 Критично для безопасности

---

### 3. Fallback на ручной выбор провайдера ✅
**Проблема:** При ошибке BIN-проверки нет возможности выбрать провайдера вручную  
**Решение:** Добавлен UI для ручного выбора провайдера при ошибке  
**Реализовано:**
- ✅ `components/donation-form.tsx` - UI для выбора провайдера (YooKassa/CloudPayments/Авто)
- ✅ `components/cloudpayments-button.tsx` - передача выбранного провайдера
- ✅ `lib/actions/payments.ts` - улучшенная обработка ошибок провайдеров
- ✅ Понятные сообщения об ошибках с предложением выбрать провайдер вручную

**Приоритет:** 🔥 Важно для UX платежей

## 🟡 Доработки (MVP-1, MVP-2)

### 4. Локализация i18n (RU/EN/AR + RTL)
**Проблема:** Только русский язык, нет поддержки EN/AR и RTL  
**Решение:** 
- Установить `next-intl` или `react-i18next`
- Создать файлы переводов (`locales/ru.json`, `locales/en.json`, `locales/ar.json`)
- Добавить RTL-поддержку для арабского
- Обновить все текстовые строки

**Файлы:**
- `app/layout.tsx` - добавить i18n provider
- `lib/i18n.ts` - конфигурация i18n
- Все компоненты - заменить хардкод на `t('key')`

**Приоритет:** ⚡ Высокий (для международной аудитории)

---

### 5. Полная история транзакций с графиками

### 6. Модерация кампаний и фондов (админ-панель)
**Проблема:** Нет UI для approve/reject кампаний и фондов  
**Решение:**
- Создать админ-панель `/admin/moderation`
- Таблица заявок с фильтрами по статусу
- Кнопки "Одобрить"/"Отклонить" с комментарием
- Уведомления пользователям о решении

**Файлы:**
- `app/admin/moderation/page.tsx` - новая страница
- `app/api/admin/campaigns/[id]/status/route.ts` - PATCH endpoint
- `app/api/admin/funds/[id]/status/route.ts` - PATCH endpoint

**Приоритет:** ⚡ Высокий (блокер для пользовательских кампаний)

---

### 7. События аналитики (tracking)
**Проблема:** Нет отслеживания событий (donation_initiated, campaign_created и т.д.)  
**Решение:**
- Добавить сервис аналитики (Sentry Events или отдельный сервис)
- Интегрировать в ключевые точки: пожертвования, подписки, создание кампаний
- Логировать события в БД для внутренней аналитики

**Файлы:**
- `lib/analytics.ts` - новый сервис
- `lib/actions/donations.ts` - добавить `trackDonationInitiated()`
- `lib/actions/campaigns.ts` - добавить `trackCampaignCreated()`

**Приоритет:** ⚡ Средний (важно для метрик, но не блокер)

---

### 8. Elasticsearch для поиска фондов/кампаний
**Проблема:** Поиск через Supabase не масштабируется  
**Решение:**
- Интегрировать Elasticsearch (через bot.e-replika.ru API или свой инстанс)
- Использовать для поиска фондов и кампаний
- Fallback на Supabase при недоступности ES

**Файлы:**
- `lib/elasticsearch.ts` - клиент для ES
- `app/api/funds/route.ts` - использовать ES для поиска
- `app/api/campaigns/search/route.ts` - использовать ES

**Приоритет:** ⚡ Средний (для масштабирования, не блокер MVP)
